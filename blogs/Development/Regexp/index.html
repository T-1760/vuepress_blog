Regular Expression 正则表达式

Tang_1997 2023/10/18 Regular Expression正则表达式

# 前言

  • Regular Expression 正则表达式（常简写：regex、regexp、RE) 也称“规则表达式”。

    • 描述了一种字符串匹配的模式（pattern）。由普通字符和特殊字符（即：元字符）组成的文字模式
    • 正则表达式的组件可以是单个字符、字符集合、字符范围、字符间的选择（和其以上组件的任意组合）

  • 正则表达式通常被用来检索、替换那些符合某个模式(规则)的文本。一句话说就是匹配有规律的东西

  • 正则表达式和通配符的区别：

    • 正则表达式（regular expression）：用来匹配文本，常搭配 grep，sed，swk三种系统命令和一些高级语言，
    • 通配符（pathname extension）：匹配文件名，大部分命令都支持
    • 两者在某些方面重合度很高，无需太过在意区别，正则表达式相较于通配符功能更强大
    符号 通配符 正则表达式
    * 零个或多个字符 前面任意的字符
    ? 单个任意字符 非贪婪匹配
    [a-z] 不包含大小写的匹配 包含大小写的匹配
    .* 以点号开头的任意字符 任意长度的字符
    \ 转义

    $ 行尾

    . 普通符号 任意单个字符

# 运算符优先级

  • 正则表达式从左到右进行匹配或查找，并遵循优先级顺序：
    • 相同优先级的从左到右进行匹配或查找
    • 不同优先级的运算先高后低
  • 正则表达式的优先级（从高到低）顺序
    运算符 描述
    \ 转义符
    ()、(?:)、(?=)、[] 选择符
    *、+、? 限定符
    ^, $, \任何元字符、任何字符 定位点和序列（即：位置和顺序）
    | 替换，"或"操作符具有高于替换运算符的优先级

# 普通字符

  • 普通字符：表示没有显式指定为元字符的所有可打印和不可打印字符
    • 包括所有大写和小写字母、所有数字、所有标点符号和一些其它符号
    • 例：e 匹配 "helllo" 的 "e"; 2 匹配 "123" 的 "2",
    • 例：hello 匹配 "helllo world" 的 "hello"

# 元字符 (meta char)

  • 元字符也称做 “特殊字符”：表示一些有特殊含义的字符。

    特别字符 含义 备注

# 转义字符

字符 含义 备注
\ 通过 \ 转义符将特殊字符转为原义字符（即：字符本身）
\x<n> 匹配十六进制字符，其中 n 为十六进制转义值（转义值必须为确定的两个数字长） 例：\x41 匹配 "A"。\x041 则表示 \x04 匹配 "1"
\u<n> 匹配 Unicode 字符，n 是四个十六进制数字表示的 Unicode 字符 例：\u00A9 匹配 @ 版权符号
\<num> 对所获取的匹配 num 的引用，其中 num 是一个正整数 例：(.)\1 匹配两个连续的相同字符
\n 标识一个八进制转义值或一个向后引用 若 \n 之前至少 n 个获取的子表达式，则 n 为向后引用
若 n 为八进制数字 (0-7)，则 n 为一个八进制转义值
\nm 标识一个八进制转义值或一个向后引用 若 \nm 之前至少有 nm 个获得子表达式，则 nm 为向后引用
若 \nm 之前至少有 n 个获取，则 n 为一个后跟文字 m 的向后引用
若前面的条件都不满足，且 n 和 m 均为 0-7 八进制数字，则 \nm 将匹配八进制转义值 nm
\<n>><m><l> 匹配八进制转义值 nml 其中 n 是 0-3 八进制数字，m 和 l 是 0-7 八进制数字

  • 非打印字符也可以是正则表达式的组成部分
  • 非打印字符的转义序列：
    字符 含义 备注
    \cx 匹配由 x 指明的控制字符（ x 的值必须为 A-Z 或 a-z 之一。否则将 c 视为一个原义的 'c' 字符） 例: \cM 匹配一个 Control-M 或回车符

# 预定义字符

字符 含义 备注
\d 匹配一个数字字符 等价于 [0-9]
\D 匹配一个非数字字符 等价于 [^0-9]
\w 匹配包括下划线的任何单词字符 等价于 [A-Za-z0-9_]
\W 匹配非下划线和任何非单词字符 等价于 [^A-Za-z0-9_]

# 定位字符

  • 定位符：指定正则表达式固定到行首或行尾
  • 定位符：描述字符串和单词的边界，
    • ^ 和 $ 分别指字符串的开始边界与结束边界，
    • \b：描述单词的前或后边界，
    • \B：表示非单词的边界
定位符 含义 备注
^ 匹配输入字符串开始的位置 若设置 RegExp 对象的 Multiline 属性，^ 还会与 \n 或 \r 之后的位置匹配
$ 匹配输入字符串结尾的位置 若设置 RegExp 对象的 Multiline 属性，$ 还会与 \n 或 \r 之前的位置匹配
A 仅匹配字符串开头 例：\Aabc 匹配 "abc_example" 字符串
Z 仅匹配字符串末尾 例：abc\Z 匹配 "example_abc" 字符串
\b 匹配一个单词边界（即：单词与空格间的位置）
\B 非单词边界匹配
  • 限定符与定位符不能一起使用。
    • 由于在紧靠换行或者字边界的前面或后面不能有一个以上位置，因此不允许诸如 ^* 之类的表达式。
  • 字边界是单词和空格之间的位置。非字边界是任何其他位置
  • \b 字符的位置是非常重要的
    • 若位于匹配的字符串的前面，它在单词的开始处查找匹配项
      • /\bCha/ 表达式匹配 "Chapter" 的首三个字符 "Cha"，此三个字符出现字边界的后面。
    • 若位于字符串的后面，它在单词的结尾处查找匹配项
      • /ter\b/ 表达式匹配 Chapter 中尾三个字符 ter，此三个字符出现在字边界的前面。
  • /\Bapt/ 表达式匹配 "Chapter" 中的 "apt"字符串，但不匹配 "aptitude" 中的 "apt"字符串
    • \B 非字边界运算符，位置并不重要，因为匹配不关心究竟是单词的开头还是结尾
    • "apt" 字符串出现在 Chapter 单词中的非字边界处，但出现在 "aptitude" 单词中的字边界处

# 限定字符

  • 限定符：指定正则表达式的一个给定组件必须要出现次数才能满足匹配。
    • 共 6 种形式：*、+ 、? 、{n} 、{n,} 、{n,m}
字符 含义 案例 备注
* 匹配前面的子表达式零次或多次 例，zo* 能匹配 "z" 、"zoo" * 等价于 {0,}
+ 匹配前面的子表达式一次或多次 例，zo+ 能匹配 "zo"、"zoo"，但不能匹配 "z" + 等价于 {1,}
? 匹配前面的子表达式零次或一次 例，do(es)?匹配 "do"、"does"、 "doxy" 中的"do" ? 等价于 {0,1}
{n} n 是一个非负整数。匹配指定的 n次 例：o{2} 不能匹配 "Bob" 中的 'o'，但能匹配 "food" 中的两个 o
{n,} n 是一个非负整数。匹配至少 n 次 例：o{2,} 不能匹配 "Bob" 中的 'o'，但能匹配 "foooood" 中的所有 o o{1,} 等价于 o+
{n,m} m 和 n 均为非负整数，其中n <= m。匹配最少 n 次且最多 m 次 例：o{2, 3}, 只匹配 "food"、foood, 但不能匹配"Bob"、"fooood"
  • * 和 + 的限定符都是贪婪的（最大匹配），
    • 它们会尽可能多的匹配文字，只有在它们的后面加上一个 ? 就可以实现非贪婪或最小匹配
      • 贪婪 /<.*>/：匹配 "<h1>标题</h1>"
      • 非贪婪 /<.*?>/：只匹配"<h1>" 和 </h1>，
      • /<\w+?>/：只匹配"<h1>"
  • ? 非贪婪模式尽可能少的匹配所搜索的字符串
    • 在任何一个其他限制符 *, +, ?, {n}, {n,}, {n,m}) 后面添加 ? 时，匹配模式是非贪婪的。
    • 而它们默认的贪婪模式则尽可能多的匹配所搜索的字符串。例："oooo" 字符串，o+ 匹配所有 'o'而 o+? 将匹配单个 "o"

# () 选择分组

  • 用 () 圆括号将所有选择项括起来，相邻的选择项之间用 | 分隔
    • () 圆括号的副作用：相关匹配会被缓存，此时可用 ?: 非捕获元放在第一个选项前来消除缓存
      • ?=非捕获元：正向预查，在任何开始匹配（()圆括号内的）正则表达式模式的位置来匹配搜索字符串，
      • ?!非捕获元：负向预查，在任何开始不匹配（()圆括号内的）正则表达式模式的位置来匹配搜索字符串

# 反向引用

  • 对一个正则表达式模式或部分模式两边添加 () 圆括号，将导致相关匹配存储到一个临时缓冲区中，所捕获的每个子匹配都按照在正则表达式模式中从左到右出现的顺序存储
    • 缓冲区从编号 1 开始，最多可存储 99 个捕获的子表达式
    • 每个缓冲区可用 \<n> 访问，其中 n 为一个标识特定缓冲区的一位或两位十进制数
    • 使用 ?:、?=、?! 非捕获元字符来重写捕获，忽略对相关匹配的保存
  • 反向引用：提供查找文本中两个相同的相邻单词的匹配项的能力
      var str = "Is is the cost of of gasoline going up up";
  var patt1 = /\b([a-z]+) \1\b/;
  console.log(str.match(patt1));
  • 反向引用：将通用资源指示符 (URI) 分解为其组件
      var str = "https://www.fly63.com:80/html/html-basic-index.html";
  var patt1 = /(\w+):\/\/([^/:]+)(:\d*)?([^# ]*)/;
  // ([^/:]+) 该子表达式匹配 `/` 和 `:` 之外的一个或多个字符  => "www.fly63.com"
  // (:\d*)?  该子表达式匹配冒号后面的零个或多个数字,只重复一次该子表达式 =>80
  // ([^# ]*) 该子表达式能匹配不包括 `#` 或空格字符的任何字符序列 => "/html/html-basic-index.html"
  arr = str.match(patt1);
  for (var i = 0; i < arr.length ; i++) {
    console.log("URI 组件：", arr[i]);
  }

# 特殊构造

  • 非获取匹配
    • 该匹配无需获取，不进行存储供以后使用
  • 预查不消耗字符
    • 在一个匹配发生后，在最后一次匹配之后立即开始下一次匹配的搜索，而不是从包含预查的字符之后开始
字符 含义 案例 备注
x\|y 匹配 x 或 y 例：(boy\|girl)s 匹配 "boys" 或 "girls"
(pattern) 匹配 pattern 并获取这一匹配。
(?:pattern) 这是一个非获取匹配，匹配 pattern 但不获取匹配结果。常搭配 \| 或字符来组合一个模式的各个部分。 例：happ(?:y\|iest) 比 happy\|happiest 表达式更简略
(?=pattern) 这是一个非获取匹配，在任何匹配 pattern 字符串开始处匹配查找字符串， 例：Windows (?=95\|98\|NT\|2000) 匹配 "Windows 2000"中的 "Windows" ，但不匹配 "Windows 3.1" 中的 "Windows" 预查不消耗字符
(?!pattern) 这是一个非获取匹配，在任何不匹配 pattern 字符串开始处匹配查找字符串 例：Windows (?!95\|98\|NT\|2000)' 匹配 "Windows 3.1" 中的 "Windows"，但不匹配 "Windows 2000" 中的 "Windows" 预查不消耗字符

# 匹配规则

# 基本模式匹配

  • 模式，是正规表达式最基本的元素，它们是一组描述字符串特征的字符
    • ^start：这个模式包含一个 ^ 特殊的字符，表示该模式只匹配以 "start" 开头的字符串
    • end$：这个模式包含一个 $ 特殊的字符，表示该模式只匹配以 "end" 结尾的字符串
    • ^ 和 $ 搭配使用 则会精确匹配

# [] 字符集/簇

  • 要建立一个表示所有元字符的字符簇，就把所有的元音字符放在一个方括号里：
    • 这个模式与任何元音字符匹配，但只能表示一个字符
      • [world]：匹配 "world" 任意一个字母（ 'w'、'o'、'r'、'l'、'd'）
      • [ \f\r\t\n]：匹配所有的空白字符
      • /^[a-z][0-9]$/：匹配仅由一个小写字母和一位数字组成的字符串
    • 用 - 连字号可以表示一个字符的范围
      • [a-z]：匹配所有的小写字母
      • [a-c]：只匹配a、b、c之一的小写字母
      • [A-Z]：匹配所有的大写字母
      • [a-zA-Z]：匹配所有的字母
      • [0-9]：匹配所有的数字
      • [1-3]：匹配 1、2、3的数字
      • [0-9\.\-]：匹配所有的数字，句号和减号
  • 在一组 [] 字符簇里使用 ^ 时，表示"非"或"排除"含义，常用予剔除某个字符
    • /^[^0-9]\w*/：匹配要求第一个字符不能是数字的字符串
    • [^a-z]：除了小写字母以外的所有字符
    • [^\\\/\^]：除了\、/、^之外的所有字符
    • [^\"\']：除了 " 双引号和 ' 单引号之外的所有字符

# 创建正则表达式对象的语法

  • 较少表达式
    • 语法：const regexp = /pattern[/flages];
    • 使用 /.../ 斜线模式不允许使用 ${...} 模板字符串。此模式是完全静态的。
  • 较长表达式
    • 语法：const regexp = new RegExp("pattern"[,"flags"]);

# 六种 flags 修饰符

  • i
    • 使用此修饰符后，搜索时不区分大小写（即：A 和 a 之间没有区别）
  • g
    • 使用此修饰符后，搜索时会寻找所有的匹配项。反之，则仅返回第一个匹配项。
  • m
    • 启动多行模式它，只影响 ^ 和 $ 的行为
    • 多行模式不仅匹配文本的开始与末尾，还匹配每一行的开始与末尾。
  • s
    • 启用 "dotall" 模式，允许 . 点匹配换行符 \n（在 字符类[4] 中有详细介绍）。
  • u
    • 开启完整的 Unicode 支持。该修饰符能够正确处理代理对。
    • [支持Unicode](https://zh.javascript.info/regexp-unicode "Unicode：修饰符 "u" 和类 \p{...}")
  • y：
    • 粘滞模式，在文本中的确切位置进行搜索
    • [粘性模式](https://zh.javascript.info/regexp-sticky "粘性标志 "y"，在位置处搜索")

# str.match()搜索

  • str.match(RegExp) 方法：在 str 字符串中寻找 regexp 的所有匹配项。
  • 该方法具有 3 种工作模式：
    • 若正则表达式具有 g 修饰符，它返回一个由所有匹配项所构成的数组：
        let str = "We will, we will rock you";
  console.log( str.match(/we/gi) ); // "We", "we"（由两个匹配的子字符串构成的数组）
    • 若没有 g 修饰符，它则会以数组形式返回第一个匹配项，索引 0 处保存着完整的匹配项，同时返回的结果的属性中还有一些其他详细信息：
      • 若正则表达式中有一部分内容被包在 () 括号里，则返回的数组可能会有 0 以外的索引（即：捕获组）
        let str = "We will, we will rock you";
  let result = str.match(/we/i);

  console.log( result[0] );     // "We"（第一个匹配项）
  console.log( result.length ); // 1
  console.log( result.index );  // 0（匹配项的位置）
  console.log( result.input );  // We will, we will rock you（源字符串）
    • 若没有匹配项，（无论是否有 g 修饰符）则返回 null 而非 [] 空数组。
        let matches_null = "JavaScript".match(/HTML/); 
  console.log(matches_null) // null

  let matches_arr = "JavaScript".match(/HTML/) || [];
  console.log(matches_arr) // 0

# str.replace() 替换

  • str.replace(regexp, replacement) 方法：使用 replacement 替换在字符串 str 中找到的 regexp 的匹配项

    • replacement 参数字符串。可以在其中使用特殊的字符组合来对匹配项进行插入：
    符号 替换字符串中的行为
    $& 插入全部匹配项的内容
    $` 插入匹配项前面的一段字符串
    $' 插入匹配项后面的一段字符串
    $n n 区间范围[0,99]，会在第 n 个括号中插入内容
    $<name> 插入名称为 name 的括号中的内容，
    $$ 插入 $ 字符
      consolo.log( "We will, we will".replace(/we/i, "I") ); // I will, we will
  consolo.log( "We will, we will".replace(/we/ig, "I") ); // I will, I will

  console.log( "I love HTML".replace(/HTML/, "$& and JavaScript") ); // I love HTML and JavaScript
